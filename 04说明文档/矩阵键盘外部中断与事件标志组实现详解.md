# STM32矩阵键盘外部中断与事件标志组实现详解

## 零、STM32外部中断线（EXTI）核心机制

### 0.1 EXTI中断线架构

STM32的外部中断控制器（EXTI）提供**16根独立的中断线**（EXTI0 ~ EXTI15），用于检测GPIO引脚的电平变化。

#### 核心规则：按引脚号分组共享
```
所有端口的第0个引脚 → 共用 EXTI0  (PA0, PB0, PC0, ..., PI0)
所有端口的第1个引脚 → 共用 EXTI1  (PA1, PB1, PC1, ..., PI1)
所有端口的第2个引脚 → 共用 EXTI2  (PA2, PB2, PC2, ..., PI2)
...
所有端口的第15个引脚 → 共用 EXTI15 (PA15, PB15, PC15, ..., PI15)
```

**关键限制**：
- ⚠️ **同一时刻，每根EXTI线只能映射到一个端口的一个引脚**
- 例如：如果PA0已映射到EXTI0，则PB0、PC0等不能再使用EXTI0
- 这是硬件层面的限制，由SYSCFG寄存器控制

### 0.2 EXTI线与中断向量的对应关系

| EXTI线 | 中断向量名称 | 说明 |
|--------|------------|------|
| EXTI0 | `EXTI0_IRQn` | 独立中断向量 |
| EXTI1 | `EXTI1_IRQn` | 独立中断向量 |
| EXTI2 | `EXTI2_IRQn` | 独立中断向量 |
| EXTI3 | `EXTI3_IRQn` | 独立中断向量 |
| EXTI4 | `EXTI4_IRQn` | 独立中断向量 |
| EXTI5~9 | `EXTI9_5_IRQn` | **共享**一个中断向量 |
| EXTI10~15 | `EXTI15_10_IRQn` | **共享**一个中断向量 |

**重要区别**：
- **EXTI0~4**：每个都有独立的中断服务函数（ISR）
- **EXTI5~9**：共用同一个ISR，需要在函数内判断具体是哪根线触发
- **EXTI10~15**：共用同一个ISR，需要在函数内判断具体是哪根线触发

### 0.3 GPIO到EXTI的映射机制

#### 映射原理
STM32通过**SYSCFG_EXTICR寄存器**（系统配置控制器）实现GPIO到EXTI的动态映射。

```c
// 函数原型
void SYSCFG_EXTILineConfig(uint8_t EXTI_PortSourceGPIOx, uint8_t EXTI_PinSourcex);
```

**参数说明**：
- `EXTI_PortSourceGPIOx`：选择端口（GPIOA~GPIOI）
- `EXTI_PinSourcex`：选择引脚号（0~15）

#### 映射示例
```
// 将PA0映射到EXTI0
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);

// 将PE2映射到EXTI2
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOE, EXTI_PinSource2);

// 将PC13映射到EXTI13
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOC, EXTI_PinSource13);
```

**底层实现**：
该函数实际是修改`SYSCFG_EXTICR[0~3]`寄存器的相应位：
- `SYSCFG_EXTICR1`：控制EXTI0~3
- `SYSCFG_EXTICR2`：控制EXTI4~7
- `SYSCFG_EXTICR3`：控制EXTI8~11
- `SYSCFG_EXTICR4`：控制EXTI12~15

每个EXTI线占用4个bit，可以表示16个端口（A~P）。

### 0.4 EXTI配置完整流程

```
// 步骤1：使能GPIO和SYSCFG时钟
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOA, ENABLE);
RCC_APB2PeriphClockCmd(RCC_APB2Periph_SYSCFG, ENABLE);

// 步骤2：配置GPIO为输入模式
GPIO_InitTypeDef GPIO_InitStructure;
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN;
GPIO_InitStructure.GPIO_PuPd = GPIO_PuPd_UP;  // 上拉或下拉
GPIO_Init(GPIOA, &GPIO_InitStructure);

// 步骤3：将GPIO映射到EXTI
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);

// 步骤4：配置EXTI触发方式
EXTI_InitTypeDef EXTI_InitStructure;
EXTI_InitStructure.EXTI_Line = EXTI_Line0;
EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;      // 中断模式
EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;  // 下降沿触发
EXTI_InitStructure.EXTI_LineCmd = ENABLE;                // 使能
EXTI_Init(&EXTI_InitStructure);

// 步骤5：配置NVIC中断优先级
NVIC_InitTypeDef NVIC_InitStructure;
NVIC_InitStructure.NVIC_IRQChannel = EXTI0_IRQn;
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 0x0F;
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0x00;
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
NVIC_Init(&NVIC_InitStructure);
```

### 0.5 中断服务函数编写规范

#### 情况1：EXTI0~4（独立中断向量）
```
void EXTI0_IRQHandler(void)
{
    // 1. 检查中断标志
    if(EXTI_GetITStatus(EXTI_Line0) == SET)
    {
        // 2. 执行用户逻辑
        // ...
        
        // 3. 清除中断标志（必须！）
        EXTI_ClearITPendingBit(EXTI_Line0);
    }
}
```

#### 情况2：EXTI5~9（共享中断向量）
```
void EXTI9_5_IRQHandler(void)
{
    // 需要逐个检查哪根线触发了中断
    if(EXTI_GetITStatus(EXTI_Line5) == SET)
    {
        // 处理EXTI5
        EXTI_ClearITPendingBit(EXTI_Line5);
    }
    
    if(EXTI_GetITStatus(EXTI_Line6) == SET)
    {
        // 处理EXTI6
        EXTI_ClearITPendingBit(EXTI_Line6);
    }
    
    // ... 依次检查EXTI7、EXTI8、EXTI9
}
```

#### 情况3：EXTI10~15（共享中断向量）
```
void EXTI15_10_IRQHandler(void)
{
    if(EXTI_GetITStatus(EXTI_Line10) == SET)
    {
        EXTI_ClearITPendingBit(EXTI_Line10);
    }
    
    if(EXTI_GetITStatus(EXTI_Line11) == SET)
    {
        EXTI_ClearITPendingBit(EXTI_Line11);
    }
    
    // ... 依次检查EXTI12~15
}
```

### 0.6 常见应用场景

#### 场景1：多按键检测（本系统）
```
// PA0 → EXTI0 (KEY1)
// PE2 → EXTI2 (KEY2)
// PE3 → EXTI3 (KEY3)
// PE4 → EXTI4 (KEY4)

// 优点：每个按键有独立的中断向量，响应速度快
// 缺点：占用较多中断资源
```

#### 场景2：单按钮多功能
```
// PA0 → EXTI0
// 短按：切换功能
// 长按：进入设置模式
// 双击：快速操作

// 实现：在中断中记录时间戳，任务中判断按压时长
```

#### 场景3：编码器输入
```
// PA0 → EXTI0 (编码器A相)
// PA1 → EXTI1 (编码器B相)
// 通过两个信号的相位差判断旋转方向和速度
```

#### 场景4：外部事件触发
```
// PB13 → EXTI13 (红外传感器)
// PC5 → EXTI5 (门磁开关)
// 检测到异常立即唤醒系统
```

### 0.7 EXTI高级特性

#### 事件模式 vs 中断模式
```
EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;  // 中断模式：触发CPU中断
EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Event;      // 事件模式：仅触发DMA/定时器，不中断CPU
```

**区别**：
- **中断模式**：CPU暂停当前任务，执行ISR，适合需要立即处理的场景
- **事件模式**：不占用CPU，可触发DMA传输或定时器捕获，适合高速数据采集

#### 软件触发EXTI
```
// 软件方式触发EXTI线（用于测试或模拟外部事件）
EXTI_GenerateSWInterrupt(EXTI_Line0);
```

#### 挂起状态查询
```
// 查询EXTI线的挂起状态（即使未使能中断也能检测）
if(EXTI_GetFlagStatus(EXTI_Line0) == SET)
{
    // 检测到电平变化
    EXTI_ClearFlag(EXTI_Line0);  // 清除标志
}
```

### 0.8 注意事项与最佳实践

#### ⚠️ 常见错误
1. **忘记清除中断标志**
   ```c
   // 错误：会导致中断持续触发，系统卡死
   void EXTI0_IRQHandler(void)
   {
       // 处理逻辑...
       // 忘记调用 EXTI_ClearITPendingBit(EXTI_Line0);
   }
   
   // 正确：必须清除标志
   void EXTI0_IRQHandler(void)
   {
       if(EXTI_GetITStatus(EXTI_Line0) == SET)
       {
           // 处理逻辑...
           EXTI_ClearITPendingBit(EXTI_Line0);  // ✅ 必须清除
       }
   }
   ```

2. **重复映射同一EXTI线**
   ```c
   // 错误：PA0和PB0不能同时使用EXTI0
   SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);
   SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOB, EXTI_PinSource0);  // ❌ 覆盖前面的映射
   
   // 正确：选择其中一个
   SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);  // ✅ 只用PA0
   ```

3. **未使能SYSCFG时钟**
   ```c
   // 错误：忘记使能SYSCFG时钟，映射无效
   SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);
   
   // 正确：先使能时钟
   RCC_APB2PeriphClockCmd(RCC_APB2Periph_SYSCFG, ENABLE);  // ✅
   SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);
   ```

#### ✅ 最佳实践
1. **优先使用EXTI0~4**：独立中断向量，代码更简洁
2. **合理分配EXTI线**：避免EXTI5~9和EXTI10~15过度拥挤
3. **中断服务函数要快**：只做标记，复杂逻辑交给任务处理
4. **使用FreeRTOS临界区保护**：调用FromISR API时必须进入临界区
5. **消抖处理**：机械按键必须软件或硬件消抖

## 一、硬件连接说明

### 1.1 引脚映射
| 按键编号 | GPIO引脚 | 外部中断线 | 功能说明 |
|---------|---------|-----------|---------|
| KEY1    | PA0     | EXTI_Line0 | 菜单键/确认键 |
| KEY2    | PE2     | EXTI_Line2 | 返回键 |
| KEY3    | PE3     | EXTI_Line3 | 上一个图标键 |
| KEY4    | PE4     | EXTI_Line4 | 下一个图标键 |

### 1.2 电气特性
- **工作模式**：上拉输入（GPIO_PuPd_UP）
- **触发方式**：下降沿触发（按键按下时电平从高到低）
- **默认状态**：高电平（未按下时为1，按下后接地为0）

## 二、按键初始化流程

### 2.1 时钟使能
```
// 1. 使能GPIOA和GPIOE端口时钟
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOA, ENABLE);
RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOE, ENABLE);

// 2. 使能系统配置控制器时钟（用于EXTI映射）
RCC_APB2PeriphClockCmd(RCC_APB2Periph_SYSCFG, ENABLE);
```

**说明**：
- `RCC_AHB1PeriphClockCmd`：使能GPIO端口时钟，让PA和PE端口能够工作
- `RCC_APB2PeriphClockCmd`：使能SYSCFG时钟，因为需要将GPIO引脚映射到EXTI中断线

### 2.2 GPIO配置
```
GPIO_InitTypeDef GPIO_InitStructure;

// 配置PA0（KEY1）
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN;          // 输入模式
GPIO_InitStructure.GPIO_Speed = GPIO_High_Speed;      // 高速响应
GPIO_InitStructure.GPIO_PuPd = GPIO_PuPd_UP;          // 内部上拉电阻
GPIO_Init(GPIOA, &GPIO_InitStructure);

// 配置PE2、PE3、PE4（KEY2、KEY3、KEY4）
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_2 | GPIO_Pin_3 | GPIO_Pin_4;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN;
GPIO_InitStructure.GPIO_Speed = GPIO_High_Speed;
GPIO_InitStructure.GPIO_PuPd = GPIO_PuPd_UP;
GPIO_Init(GPIOE, &GPIO_InitStructure);
```

**关键参数解释**：
- `GPIO_Mode_IN`：设置为输入模式，用于读取按键状态
- `GPIO_PuPd_UP`：启用内部上拉电阻，确保未按下时引脚保持高电平
- `GPIO_High_Speed`：高速模式，快速响应按键动作（但功耗略高）

### 2.3 GPIO到EXTI映射
```
// 将物理引脚连接到对应的EXTI中断线
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOA, EXTI_PinSource0);  // PA0 → EXTI0
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOE, EXTI_PinSource2);  // PE2 → EXTI2
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOE, EXTI_PinSource3);  // PE3 → EXTI3
SYSCFG_EXTILineConfig(EXTI_PortSourceGPIOE, EXTI_PinSource4);  // PE4 → EXTI4
```

**作用**：建立GPIO引脚与外部中断线的关联，使得当引脚电平变化时能够触发对应的中断。

### 2.4 EXTI中断配置
```
EXTI_InitTypeDef EXTI_InitStructure;

EXTI_InitStructure.EXTI_Line = EXTI_Line0 | EXTI_Line2 | EXTI_Line3 | EXTI_Line4;
EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;        // 中断模式（非事件模式）
EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;    // 下降沿触发
EXTI_InitStructure.EXTI_LineCmd = ENABLE;                  // 使能中断线
EXTI_Init(&EXTI_InitStructure);
```

**触发方式选择**：
- `EXTI_Trigger_Falling`：仅在电平从高到低变化时触发（按键按下瞬间）
- 其他选项：
  - `EXTI_Trigger_Rising`：上升沿触发（按键释放瞬间）
  - `EXTI_Trigger_Rising_Falling`：双边沿触发（按下和释放都触发）

**为什么选择下降沿？**
- 按键按下是用户的主动操作，响应更及时
- 避免按键释放时的抖动干扰
- 符合"按下即响应"的交互习惯

### 2.5 NVIC中断优先级配置
```
NVIC_InitTypeDef NVIC_InitStructure;

// 配置EXTI0中断（KEY1）
NVIC_InitStructure.NVIC_IRQChannel = EXTI0_IRQn;
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY;
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0x05;
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
NVIC_Init(&NVIC_InitStructure);

// 配置EXTI2中断（KEY2）
NVIC_InitStructure.NVIC_IRQChannel = EXTI2_IRQn;
NVIC_Init(&NVIC_InitStructure);

// 配置EXTI3中断（KEY3）
NVIC_InitStructure.NVIC_IRQChannel = EXTI3_IRQn;
NVIC_Init(&NVIC_InitStructure);

// 配置EXTI4中断（KEY4）
NVIC_InitStructure.NVIC_IRQChannel = EXTI4_IRQn;
NVIC_Init(&NVIC_InitStructure);
```

**优先级说明**：
- `PreemptionPriority`：抢占优先级，使用FreeRTOS的最大系统调用中断优先级，确保可以调用FreeRTOS API
- `SubPriority`：子优先级，设为0x05，多个按键同时触发时的响应顺序
- 所有按键使用相同优先级，保证公平响应

## 三、外部中断服务函数（ISR）

### 3.1 中断处理核心逻辑
以EXTI0为例（KEY1）：

```
void EXTI0_IRQHandler(void)
{
    uint32_t ulReturn;
    
    /* 进入临界段（可嵌套） */
    ulReturn = taskENTER_CRITICAL_FROM_ISR();
    
    // 检测中断标志位
    if(EXTI_GetITStatus(EXTI_Line0) == SET)
    {
        // 设置事件标志组的KEY1_DOWN位
        xEventGroupSetBitsFromISR(g_event_group, EVENT_GROUP_KEY1_DOWN, NULL);
        
        // 清除中断 pending 位
        EXTI_ClearITPendingBit(EXTI_Line0);
    }
    
    /* 退出临界段 */
    taskEXIT_CRITICAL_FROM_ISR(ulReturn);
}
```

### 3.2 关键步骤解析

#### 步骤1：进入临界区
```
ulReturn = taskENTER_CRITICAL_FROM_ISR();
```
**作用**：
- 保护后续代码不被其他中断打断
- 保存当前中断状态到`ulReturn`，用于退出时恢复
- 确保`xEventGroupSetBitsFromISR`操作的原子性

#### 步骤2：检测中断标志
```
if(EXTI_GetITStatus(EXTI_Line0) == SET)
```
**作用**：
- 确认确实是EXTI_Line0触发的中断（而非误触发）
- 防止虚假中断导致错误处理

#### 步骤3：设置事件标志
```
xEventGroupSetBitsFromISR(g_event_group, EVENT_GROUP_KEY1_DOWN, NULL);
```
**作用**：
- 向事件标志组`g_event_group`的`EVENT_GROUP_KEY1_DOWN`位（0x02）写入1
- 通知等待该事件的FreeRTOS任务有按键按下
- 使用`FromISR`版本，专门用于中断上下文

**事件标志定义**（在`includes.h`中）：
```
#define EVENT_GROUP_RTC_WAKEUP   0x01  // RTC唤醒事件
#define EVENT_GROUP_KEY1_DOWN    0x02  // KEY1按下事件
#define EVENT_GROUP_KEY2_DOWN    0x04  // KEY2按下事件
#define EVENT_GROUP_KEY3_DOWN    0x08  // KEY3按下事件
#define EVENT_GROUP_KEY4_DOWN    0x10  // KEY4按下事件
```

#### 步骤4：清除中断标志
```
EXTI_ClearITPendingBit(EXTI_Line0);
```
**作用**：
- 清除EXTI_Line0的中断pending位
- 允许下一次中断触发
- **必须执行**，否则中断会持续触发导致系统卡死

#### 步骤5：退出临界区
```
taskEXIT_CRITICAL_FROM_ISR(ulReturn);
```
**作用**：
- 恢复之前的中断状态
- 允许其他中断继续执行

### 3.3 其他按键中断函数
EXTI2、EXTI3、EXTI4的处理逻辑完全相同，仅修改对应的中断线和事件标志：

```
// EXTI2_IRQHandler → EVENT_GROUP_KEY2_DOWN (0x04)
// EXTI3_IRQHandler → EVENT_GROUP_KEY3_DOWN (0x08)
// EXTI4_IRQHandler → EVENT_GROUP_KEY4_DOWN (0x10)
```

## 四、事件标志组（Event Group）机制

### 4.1 事件标志组创建
在`app_task_init`任务中创建：
```
g_event_group = xEventGroupCreate();
```

**特点**：
- 一个事件标志组最多包含24个独立的事件位（bit 0~23）
- 每个位可以表示一个独立的事件
- 支持多任务等待同一事件或多个事件

### 4.2 事件等待机制
在`app_task_key`任务中等待按键事件：

```
EventBits_t uxBits;

uxBits = xEventGroupWaitBits(
    g_event_group,                                    // 事件标志组句柄
    EVENT_GROUP_KEY1_DOWN | EVENT_GROUP_KEY2_DOWN | 
    EVENT_GROUP_KEY3_DOWN | EVENT_GROUP_KEY4_DOWN,   // 等待的事件位（逻辑或）
    pdTRUE,                                           // 自动清除已触发的事件位
    pdFALSE,                                          // 等待任意一个事件（非全部）
    portMAX_DELAY                                     // 无限期等待
);
```

**参数详解**：
1. **第一个参数**：事件标志组句柄
2. **第二个参数**：要等待的事件位掩码
   - 使用`|`运算符组合多个事件位
   - 表示"等待这些事件中的任意一个发生"
3. **第三个参数**：是否自动清除
   - `pdTRUE`：事件触发后自动清除对应位
   - `pdFALSE`：需要手动清除
4. **第四个参数**：等待条件
   - `pdFALSE`：任意一个事件位被设置即返回（逻辑OR）
   - `pdTRUE`：所有事件位都被设置才返回（逻辑AND）
5. **第五个参数**：超时时间
   - `portMAX_DELAY`：永久等待，直到事件发生
   - 也可设置为具体tick数，超时后返回0

### 4.3 事件判断与处理
```
if(uxBits & EVENT_GROUP_KEY1_DOWN)  // 检查KEY1是否被按下
{
    // 处理KEY1按下逻辑
    // ...
}

if(uxBits & EVENT_GROUP_KEY2_DOWN)  // 检查KEY2是否被按下
{
    // 处理KEY2按下逻辑
    // ...
}
```

**工作原理**：
- `xEventGroupWaitBits`返回实际触发的事件位
- 使用`&`运算符判断具体哪个事件被触发
- 由于设置了`pdTRUE`自动清除，处理后无需手动清除

## 五、按键任务完整工作流程

### 5.1 任务主循环结构
```
static void app_task_key(void* pvParameters)
{
    uint32_t n = 1;       // 页面状态：0=图标页，1=主菜单/数据页
    uint32_t flag = 0;    // 返回层级计数
    uint8_t is_main_menu = 1;  // 主菜单标志
    int32_t i = 0;        // 当前选中的图标索引
    
    for(;;)
    {
        // 1. 等待任意按键事件
        EventBits_t uxBits = xEventGroupWaitBits(
            g_event_group,
            EVENT_GROUP_KEY1_DOWN | EVENT_GROUP_KEY2_DOWN | 
            EVENT_GROUP_KEY3_DOWN | EVENT_GROUP_KEY4_DOWN,
            pdTRUE, pdFALSE, portMAX_DELAY
        );
        
        // 2. 根据触发的事件位处理对应按键
        if(uxBits & EVENT_GROUP_KEY1_DOWN)
        {
            handle_key1(&n, &flag, &i, &is_main_menu);
        }
        
        if(uxBits & EVENT_GROUP_KEY2_DOWN)
        {
            handle_key2(&n, &flag, &i, &is_main_menu);
        }
        
        if(uxBits & EVENT_GROUP_KEY3_DOWN)
        {
            handle_key3(&n, &i);
        }
        
        if(uxBits & EVENT_GROUP_KEY4_DOWN)
        {
            handle_key4(&n, &i);
        }
    }
}
```

### 5.2 按键消抖与确认机制
以KEY1为例：

```
if(uxBits & EVENT_GROUP_KEY1_DOWN)
{
    /* 1. 禁止EXTI0中断（防止重复触发） */
    NVIC_DisableIRQ(EXTI0_IRQn);
    
    /* 2. 延时消抖（100ms） */
    vTaskDelay(100);
    
    /* 3. 再次读取GPIO电平，确认按键确实被按下 */
    if(KEY1 == 0)  // KEY1定义为PAin(0)，低电平表示按下
    {
        // 4. 执行业务逻辑
        dgb_printf_safe("[app_task_key] S1 Press\r\n");
        
        // ... 菜单切换、数据显示等逻辑 ...
    }
    
    /* 5. 重新使能EXTI0中断 */
    NVIC_EnableIRQ(EXTI0_IRQn);
}
```

**消抖原理**：
1. **第一次触发**：中断检测到下降沿，设置事件标志
2. **禁用中断**：防止按键抖动期间多次触发中断
3. **延时等待**：等待机械触点稳定（通常10-100ms）
4. **电平确认**：再次读取GPIO，确保按键仍处于按下状态
5. **恢复中断**：重新使能中断，准备下次检测

**为什么需要软件消抖？**
- 机械按键按下时会产生多次电平跳变（抖动）
- 单次按下可能触发多次中断
- 通过延时+二次确认过滤掉抖动信号

### 5.3 按键状态机
系统采用三级页面结构：

```
锁屏界面 ←→ 主菜单界面 ←→ 图标选择页 ←→ 数据详情页
  ↑              ↑              ↑              ↑
RFID刷卡      按KEY2两次     按KEY1进入    按KEY1确认
```

**状态变量**：
- `n`：页面类型（0=图标页，1=主菜单/数据页）
- `flag`：返回键计数（用于检测连续按两次返回）
- `is_main_menu`：主菜单标志（区分主菜单和数据页）
- `i`：当前选中的图标索引（0~4）

## 六、关键技术要点总结

### 6.1 EXTI_Line检测标志位的作用

**问题**：为什么在中断服务函数中要先检测`EXTI_GetITStatus`？

**答案**：
1. **多中断线共享同一个ISR**：某些STM32型号中，多个EXTI线可能共用一个中断向量
2. **防止虚假中断**：确认确实是目标中断线触发，避免误处理
3. **标准编程规范**：STM32 HAL库推荐的做法

```
if(EXTI_GetITStatus(EXTI_Line0) == SET)  // 确认是EXTI0触发
{
    // 处理逻辑
    EXTI_ClearITPendingBit(EXTI_Line0);  // 清除标志
}
```

### 6.2 事件标志组 vs 信号量 vs 队列

| 机制 | 适用场景 | 本系统中的应用 |
|-----|---------|--------------|
| **事件标志组** | 多对多通知，多个任务等待多个事件 | 按键事件通知（4个按键→1个任务） |
| **二值信号量** | 一对一同步，单个事件通知 | 火焰/烟雾状态变化通知 |
| **消息队列** | 传递带数据的消息 | OLED显示命令、EEPROM读写请求 |

**选择事件标志组的原因**：
- 4个按键独立触发，但由同一个任务处理
- 不需要传递额外数据，只需通知"哪个按键被按下"
- 支持同时等待多个事件，代码简洁

### 6.3 临界区保护的重要性

```
ulReturn = taskENTER_CRITICAL_FROM_ISR();
// ... 关键代码 ...
taskEXIT_CRITICAL_FROM_ISR(ulReturn);
```

**为什么需要临界区？**
1. **保护FreeRTOS内核数据结构**：`xEventGroupSetBitsFromISR`内部操作事件标志组的链表
2. **防止竞态条件**：如果另一个中断同时修改事件标志组，可能导致数据损坏
3. **保证原子性**：确保"读取-修改-写入"操作不被打断

**注意事项**：
- 临界区应尽量短，避免影响系统实时性
- 不能在中断临界区内调用阻塞API（如`vTaskDelay`）
- 必须成对使用`ENTER`和`EXIT`

### 6.4 中断优先级的配置原则

```
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 
    configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY;
```

**FreeRTOS中断优先级规则**：
- 数值越大，优先级越低（ARM Cortex-M特性）
- `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`定义了可以调用FreeRTOS API的最高优先级（最低数值）
- 高于此优先级的中断不能调用FreeRTOS API

**本系统配置**：
- 按键中断使用最大系统调用优先级，确保可以安全调用`xEventGroupSetBitsFromISR`
- 所有按键中断优先级相同，保证公平性

## 七、常见问题与解决方案

### 7.1 按键无响应
**可能原因**：
1. 时钟未使能（检查RCC配置）
2. EXTI映射错误（检查SYSCFG_EXTILineConfig）
3. 中断未使能（检查NVIC配置）
4. 事件标志组未创建（检查`xEventGroupCreate`）

**排查方法**：
```
// 在中断服务函数中添加调试输出
dgb_printf_safe("EXTI0 triggered!\r\n");
```

### 7.2 按键抖动导致多次触发
**解决方案**：
1. 增加消抖延时（从100ms增加到200ms）
2. 使用硬件滤波电容（10nF~100nF）
3. 改用定时器轮询方式（牺牲实时性换取稳定性）

### 7.3 事件丢失
**可能原因**：
- 任务处理速度慢，事件标志被覆盖
- 使用了`pdFALSE`自动清除，但任务未及时读取

**解决方案**：
- 提高任务优先级
- 使用队列代替事件标志组（队列有缓冲）
- 记录事件触发次数进行统计

## 八、优化建议

### 8.1 代码复用
当前4个中断服务函数代码重复度高，可提取公共宏：

```
#define KEY_ISR_HANDLER(EXTI_LINE, EVENT_BIT) \
void EXTI##EXTI_LINE##_IRQHandler(void) \
{ \
    uint32_t ulReturn = taskENTER_CRITICAL_FROM_ISR(); \
    if(EXTI_GetITStatus(EXTI_Line##EXTI_LINE) == SET) \
    { \
        xEventGroupSetBitsFromISR(g_event_group, EVENT_BIT, NULL); \
        EXTI_ClearITPendingBit(EXTI_Line##EXTI_LINE); \
    } \
    taskEXIT_CRITICAL_FROM_ISR(ulReturn); \
}

// 使用宏生成中断服务函数
KEY_ISR_HANDLER(0, EVENT_GROUP_KEY1_DOWN)
KEY_ISR_HANDLER(2, EVENT_GROUP_KEY2_DOWN)
KEY_ISR_HANDLER(3, EVENT_GROUP_KEY3_DOWN)
KEY_ISR_HANDLER(4, EVENT_GROUP_KEY4_DOWN)
```

### 8.2 动态消抖
根据不同按键调整消抖时间：

```
const uint32_t debounce_time[] = {100, 100, 80, 80};  // 不同按键不同消抖时间

if(uxBits & EVENT_GROUP_KEY1_DOWN)
{
    NVIC_DisableIRQ(EXTI0_IRQn);
    vTaskDelay(debounce_time[0]);  // 使用数组索引
    if(KEY1 == 0) { /* 处理逻辑 */ }
    NVIC_EnableIRQ(EXTI0_IRQn);
}
```

### 8.3 长按检测
扩展支持长按功能：

```
static TickType_t key_press_time = 0;

if(KEY1 == 0)
{
    if(key_press_time == 0)
        key_press_time = xTaskGetTickCount();  // 记录按下时间
    else if((xTaskGetTickCount() - key_press_time) > pdMS_TO_TICKS(1000))
    {
        // 长按超过1秒，执行特殊功能
        dgb_printf_safe("KEY1 Long Press!\r\n");
        key_press_time = 0;  // 重置
    }
}
else
{
    key_press_time = 0;  // 释放时重置
}
```

## 九、总结

本系统的矩阵键盘实现采用了**"硬件中断 + 软件消抖 + 事件驱动"**的经典架构：

1. **硬件层**：4个GPIO配置为上拉输入，通过EXTI检测下降沿
2. **中断层**：ISR中设置事件标志，使用临界区保护
3. **任务层**：按键任务阻塞等待事件，消抖后执行业务逻辑
4. **同步机制**：使用FreeRTOS事件标志组实现中断到任务的异步通知

这种设计的优点：
- ✅ 响应速度快（中断立即触发）
- ✅ CPU占用率低（任务阻塞等待，不轮询）
- ✅ 代码结构清晰（中断与业务逻辑分离）
- ✅ 易于扩展（新增按键只需添加事件位）

适用于对实时性要求较高、按键数量较少的嵌入式应用场景。
